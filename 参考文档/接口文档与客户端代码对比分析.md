## 二、接口文档合理性分析

### 🔴 问题1：创建活动接口返回格式不合理

**问题描述：**
- 文档要求返回 `data: [Activity]`（数组）
- 创建单个活动应该返回单个对象，而不是数组

**建议：**
```json
// 当前（不合理）
{
  "code": 0,
  "message": "string",
  "data": [Activity]  // 数组
}

// 建议（合理）
{
  "code": 0,
  "message": "string",
  "data": Activity  // 单个对象
}
```

---

### 🔴 问题2：创建活动请求缺少字段

**问题描述：**
- 文档只要求：title, content, location, organizer, start_time, end_time
- 但 Activity 实体有更多字段：cover_url, activity_type, quota, need_sign_in 等
- 创建活动时无法设置这些重要字段

**建议：**
创建活动请求应该包含更多字段（部分可选）：
```json
{
  "title": "string",           // 必选
  "content": "string",          // 必选
  "cover_url": "string",        // 可选，有默认值
  "activity_type": 1,           // 可选，默认值
  "location": "string",         // 必选
  "organizer": "string",        // 必选
  "start_time": "string",       // 必选
  "end_time": "string",         // 必选
  "quota": 0,                   // 可选，默认值
  "need_sign_in": true          // 可选，默认值
}
```

---

### ⚠️ 问题3：活动列表查询参数命名不一致

**问题描述：**
- 查询参数：`activity_type`（snake_case）
- 但其他接口可能使用 camelCase
- 建议统一命名规范

**建议：**
- 统一使用 snake_case（符合 RESTful 规范）
- 或统一使用 camelCase（符合前端习惯）
- 当前文档使用 snake_case，客户端已正确映射 ✅

---

### ⚠️ 问题4：错误码定义不够清晰

**问题描述：**
- 报名接口使用了自定义错误码：4091, 4092, 4093
- 但文档中没有统一的错误码说明表
- 客户端需要硬编码这些错误码

**建议：**
- 在文档开头或单独章节定义所有错误码
- 使用更语义化的错误码（如：ACTIVITY_FULL, ALREADY_ENROLLED）
- 或使用 HTTP 状态码 + 详细错误信息

---

### ⚠️ 问题5：分页参数命名不一致

**问题描述：**
- 查询参数：`pageSize`（camelCase）
- 但响应中：`pageSize`（camelCase）
- 与其他可能的 snake_case 命名不一致

**建议：**
- 统一使用 `page_size`（snake_case）或 `pageSize`（camelCase）
- 当前文档使用 camelCase，客户端已正确映射 ✅

---

**接口文档：** ISO 8601 格式（如：`2019-08-24T14:15:22Z`）
